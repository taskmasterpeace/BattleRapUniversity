# MASTER BUILD SPEC – Algorithm Institute of BattleRap (V1 Prototype)

## 0. Goal of This Prototype

**Deliverable:**
A working web app where:

* A user:

  * Creates **one battler**.
  * Chooses a **primary league** (Small Room or Main Stage).
  * Receives **AI-created battle offers** against AI battlers.
  * Accepts an offer and gets a **prep calendar**.
  * Sets **one prep focus per day** until lock.
  * At battle time, the system **simulates a 3-round battle**:

    * Segment-based peaks and averages.
    * Crowd/momentum.
  * User can **watch the battle** via a structured replay screen.
  * A **blog-style recap article** is generated and visible in a media feed.

**Out of scope for V1:**

* Human vs human matchmaking.
* Player stables (multiple managed battlers).
* Audio, voice, live text chat, generated bars.

## 2. Database Schema (Supabase / Postgres)

**NOTE FOR THE AUTONOMOUS AI:**
Generate SQL migration files to create these tables. Use snake_case. Use UUID primary keys.

### 2.1 users

Use Supabase’s `auth.users` for identity – no custom `users` table necessary unless you want extra profile fields.

Create a `profiles` table:

```sql
create table profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  display_name text not null,
  created_at timestamptz not null default now()
);
```

### 2.2 leagues

```sql
create table leagues (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  short_code text not null unique,
  round_length_minutes int not null check (round_length_minutes in (2,3)),
  base_crowd_factor numeric not null,      -- e.g., 0.4, 0.7
  writing_weight numeric not null,         -- 0..1
  performance_weight numeric not null,     -- 0..1
  booking_pace_days int not null,          -- average days between offers
  description text,
  created_at timestamptz not null default now()
);
```

Seed two leagues:

* `SMALL_ROOM` – 2 min rounds, higher writing weight.
* `MAIN_STAGE` – 3 min rounds, higher performance weight.

### 2.3 battlers

```sql
create table battlers (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references auth.users(id),
  stage_name text not null,
  region text,
  primary_league_id uuid references leagues(id),
  style_tags jsonb not null default '[]'::jsonb,  -- ["angles","gun_bars"]
  tier text not null default 'low',              -- low, mid, top, god
  is_ai boolean not null default false,
  created_at timestamptz not null default now()
);
```

### 2.4 battler_attributes

```sql
create table battler_attributes (
  battler_id uuid primary key references battlers(id) on delete cascade,
  writing jsonb not null,       -- {lyricism: int, wordplay: int, creativity: int}
  performance jsonb not null,   -- {stage_presence, crowd_control, delivery}
  personal jsonb not null,      -- {financial_stability, reputation, family_bond}
  resilience int not null check (resilience between 1 and 10),
  public_knowledge int not null default 0, -- 0..100
  xp jsonb not null default '{}'::jsonb,
  updated_at timestamptz not null default now()
);
```

### 2.5 rankings

```sql
create table rankings (
  battler_id uuid primary key references battlers(id) on delete cascade,

  wins int not null default 0,
  losses int not null default 0,
  streak int not null default 0

```

### 2.6 battles

```sql
create table battles (
  id uuid primary key default gen_random_uuid(),
```

### 2.7 prep_blocks


### 3.2 Auth & context

Implement a simple server-side auth helper that:

* Retrieves `user` from Supabase.
* Throws/returns 401 if not authenticated for protected endpoints.

### 3.3 API endpoints

#### 3.3.1 POST /api/battler/create

* **Input**:

  * `stage_name`
  * `region`
  * `primary_league_id`
  * `style_tags` (string[])

* **Logic**:

  * Create battler for authenticated user.
  * Initialize battler_attributes with baseline values (1–10 with a small pool of points).
  * Initialize rankings row.

* **Output**:

  * Battler + attributes.

#### 3.3.2 GET /api/battler/me

* **Input**: none
* **Logic**:

  * Fetch user’s battler (assume 1 for V1).
  * Include attributes, ranking, upcoming battles (next one).
* **Output**:

  * Battler, battler_attributes, rankings, `next_battle` (if any).

#### 3.3.3 GET /api/battles/offers

* **Input**: none
* **Logic**:

  * Return all `battles` where:

    * `battler_player_id` = user’s battler
    * `status` = `offered`.
* **Output**:

  * Array of battle offers.

#### 3.3.4 POST /api/battles/:id/accept

* **Input**: `battle_id` in URL.
* **Logic**:

  * Check that battle belongs to user’s battler and `status = offered`.
  * Set `status = accepted`.
* **Output**:

  * Updated battle.

#### 3.3.5 POST /api/battles/:id/decline

* Same as above, `status = declined`, optional minor reputation penalty.

#### 3.3.6 GET /api/battles/:id

* **Input**: `battle_id` in URL.
* **Logic**:

  * Return battle, rounds, segments, prep summary.
* **Output**:

  * Battle details with nested data.

#### 3.3.7 GET /api/battles/:id/prep

* **Logic**:

  * Return list of `prep_blocks` for that battle/battler.
  * Also return `days_remaining`, `lock_prep_at`.

#### 3.3.8 POST /api/battles/:id/prep

* **Input**:

  * `day_index` (int)
  * `focus` (one of `research`, `writing`, `performance`, `life`, `rest`)
* **Logic**:

  * Validate user owns the battler and battle.
  * Validate `now < lock_prep_at`.
  * Upsert `prep_blocks` row for (battle, battler, day_index).

#### 3.3.9 GET /api/news

* **Input**:

  * Optional query filters: `league_id`, `battler_id`, `type`.
* **Logic**:

  * Return recent `news_articles` ordered by `published_at DESC`.

#### 3.3.10 Cron / internal: POST /api/internal/generate-battle-offers

* **Auth**: protected by secret token.
* **Logic**:

  * For each **player battler**:

    * Check time since last battle.
    * With probability based on league’s `booking_pace_days`, generate a new `battles` record:

      * Choose league (battler’s primary).
      * Find AI opponent with similar rating.
      * Set `scheduled_at` ~ 7–14 days ahead.
      * `lock_prep_at = scheduled_at - 1 day`.
* Called daily via Supabase cron.

#### 3.3.11 Cron / internal: POST /api/internal/run-due-battles

* **Logic**:

  * Select all `battles` where:

    * `scheduled_at <= now()`
    * `status in ('accepted','locked')`
  * For each:

    * Detect no-show conditions (no prep_blocks by lock time).
    * Generate auto `rest` or `life` prep if needed; mark `no_show_player = true`.
    * Call `simulateBattle(battleId)` (see next section).
    * Set `status = 'completed'` after sim.

## 4. Simulation Module

Create `/lib/game/simulation.ts` with a pure function:

```ts
export async function simulateBattle(battleId: string, options?: { seed?: number }): Promise<void> {
  // Load battle, battlers, attributes, prep, league.
  // Run sim, write rounds, segments, update rankings.
}
```

### 4.1 Steps inside simulateBattle

1. **Load data**

   * battle row
   * league config
   * battler_player attributes + ranking
   * battler_ai attributes + ranking
   * prep_blocks for both battlers

2. **Build prep profiles**

For each battler:

```ts
type PrepProfile = {
  researchDays: number;
  writingDays: number;
  performanceDays: number;
  lifeDays: number;
  restDays: number;
};
```

Compute counts per focus.

3. **Apply prep modifiers**

Define functions:

```ts
function applyPrepModifiers(
  attributes: BattlerAttributes,
  prep: PrepProfile
): ModifiedAttributes {
  // Increase relevant attributes slightly based on focus counts.
  // Example: each writing day adds +0.2 to writing stats, capped at some max.
}
```

4. **Determine segments per round**

```ts
const segmentsPerRound = league.round_length_minutes === 2 ? 4 : 6;
```

5. **Simulate each round**

Pseudocode:

```ts
for roundIndex in [1,2,3]:
  for each battler:
    // Precompute base "writingPower" and "performancePower"
    writingPower = weightedAverage(attributes.writing)
    performancePower = weightedAverage(attributes.performance)
    baseScore = writingPower * league.writing_weight + performancePower * league.performance_weight

    // factor in personal/resilience for variance & choke likelihood

  for segmentIndex in [1..segmentsPerRound]:
    for each battler:
      executionRoll = baseScore + randomNoise(resilience, prep)
      // occasional peak if style_tags + researchDays align (angles, gun_bars, etc.)
      if isPeakSegment(styleTags, prep, roundIndex, segmentIndex):
         executionRoll *= 1.15 or similar
      // check choke
      if shouldChoke(resilience, prep, random):
         executionRoll *= 0.4
         markChokeThisRound(battler)

      record segment_score
      record event_flags: ["haymaker"], ["light"], ["choke"], etc.

  // Compute round summaries per battler
  average_score = mean(segment_scores)
  peak_score = max(segment_scores)
  consistency_score = some function of stddev
  momentum_delta = (average_score_player - average_score_ai)
  crowd_reaction = map average_score & performancePower into 0..100 adjusted by league.base_crowd_factor
```

6. **Battle outcome**

* Score rounds for each battler:

  * round winner = higher average_score (with tie logic).
* Count rounds won → final winner.
* Update:

```ts
update battles set winner_battler_id, status='completed' where id=...
update rankings set rating, wins/losses/streak where battler_id ...
insert battle_rounds / battle_segments rows
```

7. **Generate analysis summary**

* For each round, create a structured summary object:

  * `hadBigPeaks`, `wasConsistent`, `choked`, `crowdLoved`, etc.
* Use that later as input to AI for news article and battle viewer text.
