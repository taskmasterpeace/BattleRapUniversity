1. V1: What This Game Is

Working title: BattleRap Experience
Player: Manages one battler.

Opponents: AI-controlled battlers.

Leagues in V1:

League A – Small Room Circuit

2-minute rounds (shorter: more writing/angles weight).

Less crowd emphasis, more lyricism.

League B – Main Stage Arena

3-minute rounds (longer: more performance/crowd weight).

Heavy on momentum and stage presence.

Battle format:

3 rounds per battle.

Each round internally split into segments (for “peaks”):

2-minute rounds → 4 segments (30 sec each).

3-minute rounds → 6 segments (30 sec each).

Simulation runs segment-by-segment like DnD rolls → peaks + slumps.

Prep:

Each day before the battle, player chooses one focus:

research, writing, performance, life, rest.

No text bars, no typed lyrics. All abstract.

No human vs human in V1.

No-shows: handled as “autoprep + penalty” (below).

Media layer in V1:

System-generated blog-style posts after battles and big events.

“Scandals” and “stories” come from metadata + life events.

2. Core Game Flow (Player Experience)

Create Battler

Pick stage name, region, base style tags (angles/comedy/storytelling/gun bars).

Allocate starting attributes (1–10 scale) across Writing / Performance / Personal / Resilience.

Join a League

Choose League A (Small Room) or League B (Main Stage) as your primary.

League determines:

Round length.

Attribute weighting.

Pacing of offers and types of battles.

Get Booked

The league periodically creates battle offers:

Opponent (AI battler).

Date/time.

League.

Payout + stakes.

Player can accept/decline:

Accept adds battle to prep calendar.

Decline affects reputation with league.

Prep Phase (Days Before Battle)

For each day until lock_prep_at:

Choose one focus: research, writing, performance, life, rest.

System tracks how many days on each focus → prep profile.

Optional life events pop in and modify attributes / schedule.

Battle Time

At scheduled_at, the system:

Checks last prep state / no-show status.

Runs simulation: 3 rounds → multiple segments → events.

Stores:

Round scores.

Event log.

Winner.

Attribute XP / changes.

Post-Battle

Player opens Battle Viewer:

Sees round-by-round breakdown, momentum swings, crowd response, peaks vs average output.

System generates:

Analysis report for the player.

In-world blog article summarizing the battle & any scandals.

Long-term

Rank updates, more offers from leagues, new life events, stories, and potential scandals.

4. Booking Logic & No-Show Rules
4.1 Booking logic (V1)

A Supabase/Node job runs daily:

For each player battler:

Check:

time_since_last_battle

current reputation

With some probability, generate a battle offer:

Pick a league (A or B). V1: start in primary league only.

Pick an AI opponent:

Similar rating (±X).

From same or nearby region.

Schedule scheduled_at:

7–14 days from now (configurable).

Set lock_prep_at = scheduled_at - 1 day.

Offer appears in “Battle Offers” UI:

Player can:

Accept → status = accepted, battle appears in calendar.

Decline → status = declined, small league rep penalty.

4.2 No-show handling

Definition of no-show:

Player has accepted battle but:

Never opens prep screen and

Has 0 explicit prep_blocks and is inactive up to lock_prep_at.

Logic:

At lock_prep_at:

If player has no prep_blocks:

Auto-generate minimal rest/life prep pattern.

Set no_show_player = true (so we know they didn’t prep).

Apply “no-show” status effect to simulation:

Lower resilience.

Higher choke chance.

Lower consistency.

Outcome:

They still get simulated; they just look terrible.

Post-battle blog can say “Battler looked unprepared” etc.

You can later add hard forfeits, but V1: treat it as zero-prep lazy version, not a deleted battle.

5. Simulation Logic: Segment-Based “Peaks and Overall Weak”

High-level battle sim for one battle:

Pull:

Battler attributes at lock_prep_at.

Prep profile:

Count of days in each focus.

League config (weights, round length).

Derive prep modifiers:

Example (pseudo):

research_days:

angles_bonus = f(research_days)

rebuttal_success += small_amount

writing_days:

lyricism, wordplay, creativity slightly up.

performance_days:

stage_presence, delivery, crowd_control up.

rest_days:

resilience small buff; slight reduction in peak potential.

For each round (1–3):

Determine number of segments from league:

2-min → 4 segments, 3-min → 6 segments.

For each segment:

Roll “execution” for each battler:

Base = weighted sum of writing/performance attributes.

Noise = random factor biased by resilience and prep.

If random “choke” event triggered (low resilience + weak prep):

Huge penalty to that segment; mark choked = true for round.

Mark certain segments as peak segments:

Use style tags + research vs opponent to sometimes spike:

If battler has angles and high research → 1 segment per battle with bonus.

That’s the “he had a crazy angle there” moment.

From segments → round summaries:

average_score = mean(segment_score)

peak_score = max(segment_score)

consistency_score = stddev inverse

crowd_reaction = sum of segment scores mapped to 0–100, influenced by league base_crowd_factor.

momentum_delta = difference between battlers across segments.

Battle result:

Sum round results:

Score per round → round winner.

2-1 or 3-0 typical.

Apply rating changes.

Generate summary_text per round using AI from structured data.

This is where your “he had a couple moments but overall weak” emerges naturally:

High peak_score, low average_score, low consistency.

8. What “Balancing” Actually Means Here

You asked what balancing needs to be done “since they’re not competing against each other”. They are. Your battler vs AI battlers is still competition.

Balancing = preventing the system from becoming dumb or easily exploitable:

Attribute weights

Ensure lyricism doesn’t dominate everything.

In Small Room league, writing weight higher; in Main Stage, performance weight higher — but not so extreme that one dimension doesn’t matter.

Prep value

If writing prep is always strictly better than performance, players will ignore performance.

You need roughly comparable value per prep focus so different playstyles are viable.

Choke probability

Too high → game feels random + frustrating.

Too low → resilience/memorization don’t matter.

AI opponent difficulty curves

If early battles are too hard, new players get stomped and quit.

If too easy, game feels pointless.

Ratings and matchups need tuning.

League differences

Leagues should feel different, but not broken.

E.g., in Small Room, crowd reaction should still matter some, not be zero.

Balancing is mostly tuning constants in your formulas using test data and your intuitions about battle rap. It’s not mathematically perfect; it just has to “feel right” to heads.
