RACE CONDITION BUG SCENARIO:
================================================================================

Timeline showing how race condition allows 2 active battles:

T0: User has 0 active battles
    - 2 browser tabs open to /battle/offers
    - Tab A ready to accept Battle #1
    - Tab B ready to accept Battle #2

T1: User rapidly clicks Accept in both tabs (nearly simultaneous)

T2: Request A reaches API
    Step 5: Check existing battles → finds 0 ✓
    Proceeds to Step 6...

T3: Request B reaches API (before Request A updates DB)
    Step 5: Check existing battles → finds 0 ✓
    Proceeds to Step 6...

T4: Request A validates expiration → pass ✓

T5: Request B validates expiration → pass ✓

T6: Request A updates Battle #1
    UPDATE battles SET status='accepted' WHERE id=1

T7: Request B updates Battle #2
    UPDATE battles SET status='accepted' WHERE id=2

T8: BOTH requests return success!

Result: Database now has:
┌────────┬──────────┬──────────┬─────────────┐
│ Battle │ Battler  │ Status   │ Accepted At │
├────────┼──────────┼──────────┼─────────────┤
│   #1   │ Player X │ accepted │ 2025-11-25  │  ← BUG!
│   #2   │ Player X │ accepted │ 2025-11-25  │  ← BUG!
└────────┴──────────┴──────────┴─────────────┘

Player now has TWO active battles (should only have 1)!

PROPOSED FIX: Database Constraint
================================================================================

Add trigger to prevent race condition:

CREATE FUNCTION check_one_active_battle() RETURNS TRIGGER AS $$
BEGIN
  -- If setting status to accepted or locked...
  IF NEW.status IN ('accepted', 'locked') THEN

    -- Check if player already has another active battle
    IF EXISTS (
      SELECT 1 FROM battles
      WHERE battler_player_id = NEW.battler_player_id
        AND id != NEW.id
        AND status IN ('accepted', 'locked')
    ) THEN
      RAISE EXCEPTION 'Battler already has an active battle';
    END IF;

  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER enforce_one_active_battle
  BEFORE INSERT OR UPDATE ON battles
  FOR EACH ROW
  EXECUTE FUNCTION check_one_active_battle();

This makes the validation ATOMIC at database level!

Race condition scenario with constraint:

T6: Request A updates Battle #1
    → Trigger checks: no other active battles → PASS
    → Battle #1 set to 'accepted'

T7: Request B updates Battle #2
    → Trigger checks: Battle #1 is now 'accepted' → FAIL
    → Exception raised: "Battler already has an active battle"
    → Battle #2 remains 'offered'

Result: Only ONE active battle allowed (guaranteed by database)
