# House-Style Training Dataset
*The consistent-look example folder (owner, 2026-08-31: "I need a folder with all the examples consistently"). Feeds the future custom model (LoRA) once the set is big enough.*

## What's in `house-style-portraits/`
- **RAW 112×112 pixel-art busts** — the TRUE native-density examples (recovered losslessly from installed 512s by extracting the 448 area and sampling every 4th pixel). These, not the padded 512 display files, are what a model trains on.
- **One `.txt` caption per image** (kohya/LoRA convention): trigger token `brustyle` + the identity description used at generation + the eyes clause. The caption IS the identity lock — same words in, same person out.
- Sets are 4 images per battler (primary + 3 expression variants), which doubles as expression-variety coverage for training.

## Rules for adding examples
1. Only portraits generated by the **canonical pipeline** (`.claude/skills/create-battler`): 112×112, `create_image_pro`, quantized roster style ref, eyes clause in the prompt. Nothing hand-picked from the old mixed-style sprite library.
2. Add the RAW 112 (extract from the installed 512 exactly as `scripts/` recovery does, or save the PixelLab download directly).
3. Write the caption from the battler's `identity` jsonb (the DB is the identity source of truth) with the `brustyle` prefix and eyes suffix.
4. Every new battler made through the pipeline lands here automatically — the installer will be extended to drop raws + captions as it installs.

## Training plan (when the set is ready)
- **Threshold**: ~30 battlers (≈120 images with variants). Counter below.
- **Recipe** (when triggered): SDXL or pixel-tuned base + LoRA rank 16–32, 112px-native training with no upscaling augmentation, captions as-is, trigger `brustyle`. Train on cupcake (GX10) or PixelLab fine-tuning if they ship it.
- **Payoff**: likeness + consistency without per-call style references — then batch-regenerate the whole legacy roster.
